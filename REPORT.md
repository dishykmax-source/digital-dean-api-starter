# Звіт з практичної роботи №5

## Тема
Зберігання користувачів і захист паролів у SQLite в API системи «Цифровий деканат».

## Мета
Додати до наявного FastAPI API постійне сховище SQLite, шість пов’язаних таблиць, повторювану ініціалізацію та життєвий цикл облікового запису з перевіркою пароля.

## 1. Середовище виконання (середовище перевірки архіву)
- Python: 3.13.5
- SQLite: 3.46.1
- FastAPI: 0.128.2
- Pydantic: 2.13.5
- ОС перевірочного середовища: Linux; на комп’ютері студента слід вписати фактичну ОС.

Це версії середовища, у якому було перевірено переданий ZIP, а не твердження про середовище студента.

## 2. Схема бази даних
Створено шість таблиць: `status`, `user`, `role`, `user_role`, `course`, `grade`. Таблиці `user_role` та `grade` мають складені первинні ключі. Зв’язки оцінок із користувачем як студентом і викладачем використовують `ON DELETE RESTRICT`; зв’язок користувача з роллю видаляється каскадно. Для `grade.grade` задано перевірку цілого значення в діапазоні 0–100. Довідники: статуси `(0, inactive)`, `(1, active)`, `(2, blocked)`; ролі `(1, admin)`, `(2, manager)`, `(3, teacher)`, `(4, student)`.

**Доказ:** додати `02-database-schema.png` після створення локальної БД.

## 3. Ініціалізація та транзакції
`initialize_database()` створює каталог сховища, виконує DDL окремими операторами та додає довідники статусів і ролей у транзакції. Повторний запуск звіряє точні пари `id/name` і не очищає користувачів, курси, ролі чи оцінки. Кожне з’єднання вмикає та перевіряє `PRAGMA foreign_keys=ON`. Записи виконуються через `BEGIN IMMEDIATE`, `COMMIT` або `ROLLBACK`.

**Доказ:** додати термінал із двома успішними запусками `python -m app.db.initialize` та `02-database-schema.png`.

## 4. Захист паролів
Використано фіксований навчальний профіль PBKDF2-HMAC-SHA256: 600 000 ітерацій, випадкова сіль 16 байтів, результат 32 байти. Пароль зберігається як `pbkdf2_sha256$600000$<hash_hex>`, сіль — окремим lowercase hex. Перевірка обмежує формат до обчислення та порівнює байти через `hmac.compare_digest`. Відкритий пароль, хеш і сіль не повертаються у `UserPublic`.

**Доказ:** додати `03-password-hashing.png`.

## 5. Контракт API

| Метод | Шлях | Успіх | Основні відмови |
|---|---|---|---|
| POST | `/api/v1/users` | 201, `UserPublic` | 409 дубль, 422 валідація, 500 БД |
| DELETE | `/api/v1/users/{user_id}` | 204 без тіла | 404 немає, 409 є оцінки, 422 id, 500 БД |
| PATCH | `/api/v1/users/{user_id}/block` | 200, `UserPublic` зі статусом 2 | 404 немає, 422 id, 500 БД |
| POST | `/api/v1/auth/login` | 200, JSON boolean | 422 тіло, 500 БД |

Реєстрація без `status_id` створює `inactive` (0). Лише активний (1) користувач із правильним паролем отримує `true` під час входу. Блокування встановлює лише статус 2 і є ідемпотентним. Видалення користувача з оцінкою заборонене та не змінює пов’язані записи.

**Доказ:** додати `06-swagger-endpoints.png` та скриншоти фактичних запитів Postman.

## 6. Автоматизовані перевірки

У перевірочному середовищі виконано:

```bash
python -m pytest -q tests/test_practice05_accounts.py
```

Результат: **12 passed**.

Також виконано повний набір:

```bash
python -m pytest -q
```

Результат у наявному середовищі: **104 passed, 41 failed**. Причина відмов — не встановлені/не ті версії залежностей попередніх практичних: відсутній модуль `Crypto` (PyCryptodome), а встановлена версія `cryptography` не містить потрібного `cryptography.hazmat.primitives.hpke`. У `pyproject.toml` зафіксовані `pycryptodome==3.24.0` та `cryptography==48.0.1`; спроба встановити їх у перевірочному контейнері не вдалася через відсутність мережевого доступу. Це обмеження середовища, а не результат успішного повного регресійного прогону. На комп’ютері студента необхідно виконати `python -m pip install -e ".[dev]"` і повторити повний тестовий набір.

**Доказ:** додати фактичні `04-practice05-tests.png` і `05-full-test-suite.png` після локального запуску. Якщо повний набір після встановлення залежностей пройде, оновити цей розділ реальним результатом.

## 8. Git та історія змін
Наданий ZIP не містить каталогу `.git`. Тому неможливо перевірити батьківський коміт `practice-04`, створити коректний `practice-05-base` від історії попередньої роботи або достовірно показати власні коміти після baseline. Цей ZIP містить код і файли практичної №5, але не Git-історію. Щоб завершити цей пункт без підробки історії, потрібно перенести ці зміни в повний клон власного форку та виконати інструкції з `PRACTICE-05.md`/методички.

**Доказ:** додати `09-github-commits-tags.png` після публікації реальної гілки й тегів.

## 9. Обмеження та безпека
Це локальна навчальна реалізація, призначена лише для `127.0.0.1` і синтетичних даних. Маршрути видалення та блокування не мають адміністративної авторизації. Булевий login не створює сесію й не захищає інші маршрути. SQLite-файл не шифрується автоматично. Не додавати до Git файл БД, sidecar-файли, дампи облікових даних, `.env` або справжні секрети.

## 10. Висновок
У переданому проєкті реалізовані схема SQLite з шістьма таблицями, повторювана ініціалізація, PBKDF2-HMAC-SHA256 та чотири маршрути керування обліковими записами. Дванадцять тестів практичної №5 пройшли у перевірочному середовищі. Повна регресія попередніх практичних потребує встановлення закріплених криптографічних залежностей; Postman, перезапуск сервера та Git-публікація мають бути підтверджені локально.

## Глосарій
- **API** — прикладний програмний інтерфейс.
- **Автентифікація** — перевірка заявленої ідентичності.
- **Авторизація** — визначення дозволених дій після встановлення ідентичності.
- **FK** — зовнішній ключ, що забезпечує цілісність посилань.
- **PBKDF2** — функція виведення ключа на основі пароля з керованими ітераціями.
- **SQLite** — вбудована реляційна система керування базами даних.
- **Сіль** — випадкові дані, що додаються до окремого парольного запису.
- **Транзакція** — група змін, що завершується повністю або відкочується.
