## 4. Реалізований контракт API

| Метод | Шлях | Код успіху | Призначення |
|---|---|---:|---|
| GET | `/health` | 200 | Перевірка готовності |
| POST | `/api/v1/students` | 201 | Створення запису |
| GET | `/api/v1/students` | 200 | Список записів; підтримує фільтр |
| GET | `/api/v1/students/{student_id}` | 200 | Отримання за UUID |
| PATCH | `/api/v1/students/{student_id}` | 200 | Часткове оновлення |

Коди помилок: 404 — запис не знайдено; 409 — конфлікт унікальності email; 422 — помилка валідації, невідоме поле або порожнє оновлення.

## 5. Реалізація індивідуального варіанта №3
До моделей створення, читання й часткового оновлення додано поле `academic_status`. Воно має тип переліку `AcademicStatus` з такими навчальними значеннями:

- `active` — навчається;
- `academic_leave` — академічна відпустка;
- `expelled` — відрахований;
- `graduated` — завершив навчання.

Набір значень визначено явно для навчального завдання. Невідомий статус відхиляється Pydantic з кодом 422. Для списку реалізовано необов'язковий параметр `academic_status`, наприклад `/api/v1/students?academic_status=active`.

## 6. Перевірка
У каталозі `tests` підготовлено перевірки:
1. health повертає точне тіло `{"status":"ok"}`;
2. створення запису та серверний UUID;
3. відхилення некоректної email-адреси;
4. отримання списку;
5. отримання наявного й відсутнього запису;
6. PATCH змінює лише передане поле;
7. невідомі поля та порожній PATCH відхиляються;
8. фільтрація за `academic_status`;
9. невідоме значення статусу відхиляється;
10. повторна email-адреса спричиняє конфлікт 409.

Команда запуску: `python -m pytest -q`. Фактичний результат виконання потрібно вставити після запуску у вашому середовищі.

## 7. Перевірка Postman
Підготовлено колекцію Postman Collection 2.1 з послідовними запитами для health, створення, списку, отримання, PATCH, помилкових даних, невідомого статусу, фільтрації та конфлікту email. Колекція зберігає UUID створеного запису в змінній `student_id`.

## 8. Висновок
У результаті роботи створено модульний навчальний API «Цифровий деканат» на FastAPI. Реалізовано типізовані суворі моделі Pydantic, серверну генерацію UUID, тимчасовий репозиторій, контроль унікальності email, операції створення й читання, часткове оновлення PATCH та контрольовані HTTP-помилки. Для індивідуального варіанта №3 реалізовано поле `academic_status`, перелік допустимих значень і фільтрацію списку за цим полем. Підготовлено автоматизовані тести й колекцію Postman.
